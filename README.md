# 投产需求清单管理工具

内网部署的投产需求管理工具，支持多人协作、GitHub/GitLab 分支管理、SQL 脚本下载、用户与角色权限管理。

## 架构

```
用户浏览器 ──→ nginx (:80) ────→ index.html (前端)
                  │
            /api/* proxy_pass
                  │
                       └──→ Windows Node.js (:3000) ←── 你的本地机器
                       ├── start.js
                       ├── data.json          (共享业务数据)
                       ├── git-config.json    (Git Token，管理员配置)
                       └── users.json         (用户与角色)
```

- **前端**：纯静态 HTML，部署在 nginx 服务器，所有用户通过浏览器访问
- **后端**：Node.js，运行在你的 Windows 机器上，处理数据读写和版本控制
- **Git Token**：存在服务端 `git-config.json`，管理员配一次，全员可用

## 功能

- **投产窗口管理**：按年份组织投产窗口，新建/编辑/删除，新建时只需日期；投产手册生成前补齐两位投产人员并选择 core / gl / cm 投产包
- **需求清单**：每个窗口内管理需求，含代码模块、SQL 脚本、评审状态
- **需求清单导出**：按投产窗口导出 Excel，包含序号、需求名称、需求编号、解决人、业务人员
- **统计面板**：一眼查看窗口内需求总数、已评审、已合并、SIT/UAT 报告收集情况
- **延期追踪**：延期需求汇总展示，支持恢复上线
- **历史需求搜索**：左侧栏支持按需求名称、编号、人员、分支等关键字模糊查询，输入关键字后按回车定位相关投产窗口
- **Git 集成**：一键获取 GitHub / GitLab 项目列表和分支，下拉选择
- **SQL 管理**：支持查询/执行/回退三段式 SQL，单个下载或打包下载 ZIP
- **投产手册生成**：按投产窗口生成 Word 投产手册，自动带出需求、SQL、API、投产人员、投产包清单和包上传步骤
- **版本冲突检测**：多人同时编辑时，后保存者会收到冲突提示
- **搜索过滤**：按需求名称/编号实时过滤
- **用户管理**：管理员可维护用户，支持管理员、配置人员、普通开发人员三类角色

## 部署

### 第一步：启动后端（你的 Windows 机器）

```cmd
:: 方式一：默认密码
node start.js

:: 方式二：自定义管理员密码
set ADMIN_PASSWORD=你的密码
node start.js

:: 启动后输出:
:: http://localhost:3000
```

### 第二步：部署前端（nginx 服务器）

1. 把 `index.html` 放到 nginx 的 html 目录
2. 把 `nginx.conf` 中的 `你的Windows内网IP` 改为 Windows 的实际内网 IP
3. reload nginx

### 第三步：登录并配置 Git Token

管理员打开页面 → 使用默认账号 `admin` 和启动密码登录（默认 `admin123`）→ 点左下角「仓库设置」→ 配置 Token

首次启动时会自动生成 `users.json`，并创建默认管理员账号：

| 用户名 | 默认密码 |
|--------|----------|
| `admin` | `ADMIN_PASSWORD` 环境变量，未设置时为 `admin123` |

## 数据存储

| 文件 | 位置 | 内容 |
|------|------|------|
| `data.json` | Windows | 投产窗口、需求数据，带版本号 |
| `git-config.json` | Windows | Git Token，管理员可写 |
| `users.json` | Windows | 用户、角色、密码哈希及管理员可查看的密码文本 |

## 角色权限

| 操作 | 普通开发人员 | 配置人员 | 管理员 |
|------|--------------|----------|--------|
| 查看需求、统计面板 | ✓ | ✓ | ✓ |
| 搜索、下载 SQL/API | ✓ | ✓ | ✓ |
| 编辑需求里的代码模块、数据库清单、API | ✓ | ✓ | ✓ |
| 新建/编辑/删除投产窗口和需求 | ✗ | ✓ | ✓ |
| 调整 SIT/UAT/评审/合并/延期状态 | ✗ | ✓ | ✓ |
| 管理用户 | ✗ | ✗ | ✓ |
| 查看用户密码 | ✗ | ✗ | ✓ |
| 修改自己的密码 | ✓ | ✓ | ✓ |
| 修改 Git Token | ✗ | ✗ | ✓ |

> 已经按哈希保存且没有密码文本的旧用户，管理员界面会显示“已加密”；重置或用户自行修改密码后即可查看新密码。
